The Teams

LLM Serving Team

Runs 5 production models: a 70B flagship model (4 GPUs per replica, 3 replicas for HA), two 13B domain models, and two 7B models. Statically provisioned 48 H100s. Traffic is 90% daytime U.S. hours; at night, 36 GPUs sit idle but reserved.

48 top-tier GPUs reserved 24/7 ~75% sit idle overnight models never shut down when idle

GenAI Platform Team

Exposes models as APIs to 12 internal applications. Traffic is bursty — 3x spikes during market open, near-zero on weekends. Provisioned for peak at all times: 16 A100s dedicated, using 4 on average. Each API consumer gets a full GPU regardless of load.

16 GPUs reserved full-time only 25% used on average sized for busiest hour, idle the rest

Content Safety Team

Deploys 14 guard models — toxicity filters, PII detectors, prompt injection classifiers. Each model is 1–3GB but runs on a full A100 (80GB) because Kubernetes only supports nvidia.com/gpu: 1. 14 GPUs, 2.5% VRAM utilization each.

14 full GPUs for 14 tiny models each model uses 2.5% of the GPU no way to share one GPU among them

Data Science & Experimentation

40 data scientists with Jupyter notebooks. Each notebook requests 1 GPU on launch. On a typical Tuesday: 30 notebooks running, 8 are active experiments, 12 are idle (user in meetings), 10 haven’t been touched since last week. No culling configured. No visibility into who’s using what.

30 GPUs held by notebooks only 27% actually computing no auto-shutdown for idle sessions

How GPUs Are Managed Today

Current State

  • Static namespace quotas — each team gets a fixed GPU count at the start of quarter
  • No borrowing — if Team A has 10 idle GPUs and Team B is queued, Team B waits
  • GPU allocation via ServiceNow ticket — 3–5 day turnaround
  • nvidia.com/gpu: 1 is the only resource request — no GPU type, no memory, no MIG
  • No cost visibility — nobody knows what their GPU usage costs
  • Training jobs run on the same cluster as inference with no priority separation
  • Once a week, a training job saturates the cluster and inference latency spikes to 10x

Technical Requirements

  • Self-service GPU access for data scientists — no tickets
  • Small models on GPU slices, not whole GPUs
  • Inference GPUs that scale up during market hours and release at night
  • Training can use idle inference capacity without affecting production SLAs
  • Dashboard showing each team’s GPU cost so leadership can optimize spend
  • Air-gapped deployment — all clusters are disconnected, FIPS required
  • Single management plane across all 3 clusters
