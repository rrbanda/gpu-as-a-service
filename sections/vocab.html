MIG

Multi-Instance GPU
tap to flip

Hardware-level GPU partitioning. Carves one A100 into up to 7 isolated slices, each with dedicated compute, memory, and cache. Like splitting one large office into 7 soundproof private offices — each tenant gets their own key, walls, and power meter.

Kueue

Fair-share GPU scheduling
tap to flip

Fair-share GPU scheduler. GPU scheduling is a business policy problem, not merely a Kubernetes configuration. Kueue enforces that policy — quotas, borrowing, preemption, and priority across teams. Like the grid operator that decides which district gets power during peak demand.

tap to flip back

KServe

Model serving & scale-to-zero
tap to flip

CNCF Incubating project for model lifecycle — deploy, version, scale, and monitor. Provides scale-to-zero: idle models release GPUs entirely, cold-start on demand. The electricity meter stops when you turn off the lights — and starts instantly when you flip the switch.

GPU Credits

Normalized cost abstraction
tap to flip

A unit that normalizes different GPU types into a common currency. H100 = 100 credits, A100 = 60, MIG slice = 10. Like kilowatt-hours on your electricity bill — you don’t care which generator produced the power, you care about consumption. Teams get credit budgets, not GPU counts.

DRA

Dynamic Resource Allocation
tap to flip

Kubernetes API that replaces nvidia.com/gpu: 1 with rich, declarative GPU claims. Saying nvidia.com/gpu: 1 is like telling a recruiter “hire me two people.” DRA is like saying “hire me two engineers with Go experience, Kubernetes knowledge, and 5 years backend” — GPU type, memory, MIG profile, topology, all in one request.

llm-d

Distributed inference middleware
tap to flip

CNCF project (Red Hat, Google, IBM, NVIDIA) that adds KV-cache-aware routing, disaggregated prefill/decode, and prefix caching on top of vLLM. Turns LLM serving into a stateful routing problem.

tap to flip back

WVA

Workload Variant Autoscaler
tap to flip

llm-d’s inference-aware autoscaler. Scales replicas based on queue depth, KV-cache pressure, and token throughput — not generic CPU/memory. Supports minReplicas: 0 for scale-to-zero and cost-optimized variant selection.

EPP

Endpoint Picker
tap to flip

llm-d’s routing brain. For each incoming request, EPP checks the KV-Cache Indexer to find which replica already has the most relevant context loaded — then routes there. Avoids redundant prompt recomputation.

KEDA

Event-Driven Autoscaling
tap to flip

Kubernetes autoscaler that scales on external metrics — queue depth, custom Prometheus queries, or WVA’s wva_desired_replicas metric. Bridges the gap between “no demand” and “full auto-scale.”

Compute Profiles

Self-service GPU abstraction
tap to flip

Evolution of Hardware Profiles — admin-defined GPU “t-shirt sizes” that data scientists select from a dropdown. Instead of writing YAML, users pick “Small GPU” or “Large Inference” — the platform maps this to the right GPU type, MIG profile, and Kueue queue. Targeted for RHOAI 3.7.

Kubernetes operator for Ray

Manages Ray clusters on Kubernetes. Ray Serve enables multi-model LLM inference with built-in replica autoscaling (min/max replicas per model, target_ongoing_requests). Also handles distributed training, fine-tuning, and multi-node GPU jobs via RayJob/RayCluster.

Why GPUaaS for AI Is Different

The Three Problems

Problem 1: Memory Claimed ≠ Demand Served

Serving frameworks claim GPU memory upfront regardless of actual work. A 2 GB model on an 80 GB GPU is like parking a bicycle in a semi-truck spot — the space is “taken,” but 97% of it is empty.

Problem 2: GPU Scheduling Is a Business Policy Problem

Kubernetes treats GPUs as opaque integer counters — nvidia.com/gpu: 1. No type, no memory, no slicing. Four teams sharing a cluster have no mechanism for fair-share allocation, quota enforcement, or cost attribution. This isn’t a scheduler tuning problem — it’s an enterprise service policy that doesn’t exist yet.

Problem 3: Regulated Industries Add Hard Constraints

Air-gapped deployment, audit trails, multi-vendor GPU procurement policies, FIPS compliance, and disconnected operation are non-negotiable for financial services. Many AI infrastructure tools assume cloud connectivity.

How the Platform Addresses Regulatory Constraints
  • FIPS 140-2 validated cryptography — all TLS, certificate, and key management uses FIPS-validated modules
  • Signed OCI artifacts — every container image, Helm chart, and operator bundle is signed with cosign and verified at deploy time
  • Supply chain integrity — SLSA provenance for all Red Hat-built images; SBOM generation for audit
  • Disconnected / air-gapped operation — full mirror registry support; no outbound network required post-install
  • FedRAMP-capable architecture — OpenShift has achieved FedRAMP High authorization; AI services inherit the control plane
  • Dedicated Product Security team — vulnerability scanning, CVE response SLAs, and proactive security advisories
