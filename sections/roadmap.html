Product Evolution

RHOAI GPUaaS Roadmap

GPU-as-a-Service capabilities are delivered incrementally across RHOAI releases. This roadmap shows the progression from visibility to governance to self-service.

See — Make GPUs Visible
3.5
RHOAI 3.5 (Aug 2026)
  • GPU Topology and Utilization Dashboard (Admin)
  • Kueue scheduling info in Workbenches
  • MaaS observability dashboard: token usage, rate limits (TP)
  • MLflow GA: experiment tracking, agent tracing, model registry
  • llm-d observability: Prometheus metrics + distributed tracing
Theme: Visibility — see what GPUs are doing
Govern — Establish Policy
3.6
RHOAI 3.6 (Nov 2026)
  • Kueue Quota Dashboard
  • Workload Observability Dashboard
  • DRA support (Developer Preview)
  • Per-tenant GPU usage export (showback)
  • Compute Profiles v1
  • KEDA GA for llm-d autoscaling
Theme: Governance — control who gets what
Act — Enable Self-Service
3.7
RHOAI 3.7 (~Q1 2027)
  • Scheduling explainability (“why am I pending?”)
  • Self-service GPU allocation via calendar view
  • GPU cost attribution per team
  • Advanced Compute Profiles (software stack, cost, queue info)
Theme: Self-service — users act without admin tickets
3.8
RHOAI 3.8 (~Q2 2027)
  • Self-service GPU pool wizard
  • GPU slice provisioning with quota enforcement
  • Idle GPU detection + automatic reclamation
Theme: Automation — platform acts proactively
Strategic framework: See → Govern → Act. RHOAI 3.5 makes GPUs visible. 3.6 adds governance controls. 3.7–3.8 enable self-service and automation. Each release builds on the previous — you cannot govern what you cannot see, and you cannot enable self-service without governance guardrails.

Hardware Profiles → Compute Profiles

Hardware Profile (Today)

  • GPU count, tolerations, node selectors
  • No GPU type metadata
  • No software stack info
  • No cost info
  • No queue/availability info

Compute Profile (Target)

  • GPU model, memory, architecture, MIG slice
  • Default runtime, compatible workbench images
  • Allowed groups, team-scoped visibility
  • Per-GPU-hour rate, chargeback code
  • ClusterQueue assignment, availability (“2/8 used”), priority
