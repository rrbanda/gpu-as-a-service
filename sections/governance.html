Layer 3 Deep Dive — Governance

Kueue Configuration

When Kueue applies — and when it doesn’t. Do not add Kueue merely because GPUs are involved.

⚡ Think: the grid operator during peak demand — decides which district gets power, lets idle capacity flow to neighbors, and sheds non-critical load before the grid fails. GPU scheduling is a business policy problem, not a Kubernetes configuration problem.

Decision Framework

Scenario A: Dedicated Inference Pool

WVA optimizes the pool directly. No multi-tenant contention.

Kueue: NO

Scenario B: Inference + Training Shared

Prevents training from starving production inference.

Kueue: YES

Scenario C: Service-Tier Boundaries

Critical (48 GPUs guaranteed, no preempt) / Standard (32, best-effort, can borrow) / Elastic (16, preemptible, spot-like)

Kueue: YES

ClusterQueue with Cohort

ClusterQueue — 16 H100 quota, borrowing up to 8 more, fair-share weight 2 
apiVersion: kueue.x-k8s.io/v1beta2
kind: ClusterQueue
metadata:
  name: team-llm-serving
spec:
  namespaceSelector: {}
  cohortName: gpu-shared-pool
  resourceGroups:
  - coveredResources: ["cpu", "memory", "nvidia.com/gpu"]
    flavors:
    - name: h100-80gb
      resources:
      - name: "nvidia.com/gpu"
        nominalQuota: 16
        borrowingLimit: 8
  preemption:
    withinClusterQueue: LowerPriority
    reclaimWithinCohort: Any
  fairSharing:
    weight: 2

GPU Credit System

Kueue Resource Transformations — H100 = 100 credits, A100 = 60, MIG = 10 
apiVersion: config.kueue.x-k8s.io/v1beta2
kind: Configuration
resources:
  transformations:
  - input: nvidia.com/gpu-h100
    strategy: Replace
    outputs:
      gpu_credits: 100   # H100 @ $3.20/hr
  - input: nvidia.com/gpu-a100
    strategy: Replace
    outputs:
      gpu_credits: 60    # A100 @ $1.92/hr
  - input: nvidia.com/gpu-a100-mig-1g
    strategy: Replace
    outputs:
      gpu_credits: 10    # MIG 1g.10gb slice
Note: 600 credits buys 6 H100s or 10 A100s or 60 MIG slices. GPU credits normalize cost across heterogeneous GPU types.
